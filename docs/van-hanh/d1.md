## 2. Chạy nhập

```bash
npm run import -- --from=snapshot                              # chỉ đọc, đếm, kiểm
npm run import -- --from=snapshot --db=d1.sqlite --migrate     # tạo bảng rồi nhập vào một file SQLite
npm run import -- --from=snapshot --sql=data/import.sql        # ghi các câu lệnh ra file (khoảng 9 MB, không vào git)
npm run import -- --from=b2 --db=d1.sqlite                     # đọc bucket của admin cũ (cần B2_ENDPOINT, B2_BUCKET, B2_KEY_ID, B2_APPLICATION_KEY)
```

- **Chạy lại được:** cùng nguồn cho cùng dòng. Dòng đã biến mất khỏi nguồn bị xóa; bảng do site và admin mới ghi (`page_view`, `registration`, `user`, `audit_log`, `setting`, `notice`, `redirect`) và các cột admin sửa sau nhập (`area.visible`, `calendar_event.registration_open`, các cột `updated_at`) không bị đụng.
- **Hỏng thì không ghi gì:** một nguồn không có dòng nào (đọc hỏng) làm lệnh dừng trước khi ghi, trừ khi thêm `--allow-empty`; ghi vào file SQLite là một giao dịch, hỏng giữa chừng thì lùi hết.
- **Sự kiện đã có người đăng ký** không bị xóa dù nguồn bỏ nó (khóa ngoại chặn, lệnh báo lỗi `FOREIGN KEY`).
- **Snapshot thiếu Danh Tăng?** Chạy `npm run snapshot:fetch` (đã thêm `danh-tang.json`).

## 3. D1 cục bộ (đã thử)

```bash
npx cf d1 migrations apply 00000000-0000-4000-8000-000000000001 --local --persist-to .cf-state
```

Lệnh tạo file SQLite của D1 mô phỏng trong `.cf-state/v3/d1/miniflare-D1DatabaseObject/`; nhập vào chính file đó bằng `--db=<đường dẫn>`. `cf d1 query --local` hiện báo không có tương đương cục bộ, nên kiểm bằng cách mở file SQLite. Thư mục `.cf-state` là trạng thái cục bộ, không đưa vào git.

## 4. Giới hạn của D1 đã tính vào mã

- Một câu lệnh tối đa 100 KB: dòng lớn hơn được ghi theo từng đoạn 40 KB (câu đầu chèn dòng, các câu sau nối thêm). Một tượng có bài 155 KB. Lệnh dừng và liệt kê nếu còn dòng nào không cắt được.
- Mỗi câu lệnh nhập tối đa 25 dòng.
- Khóa ngoại được D1 thi hành; thứ tự câu lệnh đã đi từ bảng được trỏ tới đến bảng trỏ.

## 5. Đọc từ D1 trong site (T24)

`CONTENT_SOURCE=d1` chọn nguồn `src/libs/content/sources/d1.ts`, đọc binding `DB` của Worker (không có binding thì báo "thiếu binding DB"). Cả ba nguồn (`snapshot`, `b2`, `d1`) phải trả y hệt nhau: `npm test -- contract` kiểm điều đó trên snapshot thật. Sửa nguồn nào cũng chạy lại bộ này.

- D1 đọc lại mỗi phút (như B2); khi admin mới có, trang cập nhật ngay nhờ `revalidateTag` (T24, **chưa làm**).
- Bài trùng slug với bài đứng trước nằm trong D1 nhưng ra khỏi danh sách, cho tới khi được đặt slug khác.
